## Key design decisions

1. **Re-export types through `types.ts` rather than duplicating them.** The data layer in `data.ts` owns the type definitions (StageDef, SourceDef, SlaPolicies, TeamMember, etc.) because the helpers and the type shapes are tightly coupled. The new `types.ts` is a pure re-export barrel so callers can do `import type { LeadStage, SlaStatus } from "@/modules/leados/types"` without needing to know the data-layer path. Satisfies the spec's required file structure without fragmenting the source of truth.
2. **Touch only the leados entry in the registry.** Per the task instructions ("Touch ONLY the leados entry. Keep all other entries intact."), I added the `LeadOSView` import alongside the existing module imports (alphabetical-ish grouping with the other 4 already-wired views) and replaced only `placeholderFor("leados")` → `LeadOSView`. The `placeholderFor` import is kept because `quoteflow` / `connect` / `control` / `ownerAi` / `audit` / `settings` still use it.
3. **No i18n changes needed.** Foundation Task 1 had already added the full 131 `leados.*` keys × 3 locales. I verified every call site resolves and that the stage.* / common.* / misc.noResults keys the module references are also present. Adding duplicate keys would have caused a TS "duplicate object literal property" error or shadowed the existing values.
4. **SLA tones use cyan for on-track, amber for warning, rose for breach** (with `animate-pulse-dot` on warning/breach). This matches the spec exactly. The `SLA_TONE` map in `shared.tsx` is the single source of truth — the dashboard gauge, table badge, Kanban dot, detail timers, and SLA tracker tables all derive from the same `getSlaStatus(lead)` + tone lookup.
5. **Stage colors via the `tone` field in `LEAD_STAGES`** (cyan / muted / lime / amber / violet / success / rose). The `success` tone maps to emerald via `toneClasses("success")` in `utils.ts`. `StageBadge` uses `bg-current/10` + `border-current/30` + the stage's `text-*` class so the badge reads as a single-color chip per stage. Won (emerald) and Lost (rose) are flagged `closed: true` so SLA calculations and pipeline stats can skip them.
6. **LeadDetail Sheet owns the stage switcher** (7 inline buttons) and propagates changes back to the parent via `onStageChange`. This means dragging a card in the Kanban AND clicking a stage button in the detail Sheet both fire the same callback path — the parent (LeadOSView) updates `selectedLead`, and the Sheet's local `localStage` mirrors it.
7. **AI Lead Agent is mock-only.** The 4 actions (Analyze / Qualify / Summarize / Next-best-action) each return a hardcoded insight paragraph (BANT score, buying signals, summary, recommended next step) with a 700ms simulated loading delay + violet spinner. The result panel renders the tone-colored title + body. This satisfies the "AI Lead Agent mini-panel" requirement without needing a real backend; the AI Owner module (Task 10) can later wire the real assistant.
8. **Kanban drag uses @dnd-kit (not button-based reorder).** Per the spec's explicit mention of `@dnd-kit`, the Kanban uses `DndContext` + `useDraggable` + `useDroppable` + `DragOverlay`. PointerSensor with 5px activation constraint lets users click cards without accidentally starting a drag. The `DragOverlay` shows a rotated clone of the card with a spring drop animation.
9. **External + internal search.** `LeadsTable` accepts an optional `externalQuery` prop (driven by the LeadOSView toolbar search) AND maintains its own `internalQuery` for when it's used standalone. The effective query is `externalQuery ?? internalQuery`. This lets the toolbar search filter the table without duplicating the search input.
10. **All charts use theme tokens + `isAnimationActive={false}`.** Recharts fills reference CSS variables (`var(--accent-lime)`, `var(--accent-cyan)`, `var(--success)`, etc.) so the charts match the dark enterprise theme. Animations are disabled for snappy SSR + to avoid layout shift. Tooltips use a shared `CHART_TOOLTIP_STYLE` constant with `var(--popover)` / `var(--border)` / `var(--popover-foreground)`.
